WHAT SMARTGROWINFOTECH.COM ALREADY RUNS  [LIVE — verified from the live site]
  · Next.js, App Router (/_next/static/chunks/app/layout-*.js, app/brand/page-*)
  · React Server Components (main-app chunk present)
  · shadcn/ui token contract — the live :root carries the exact shadcn variable

    --muted --accent --destructive --border --input --ring --radius
  · Tailwind CSS

    "* Fallback" @font-face entries — the next/font signature)
  · Satoshi referenced as `Satoshi, var(--font-body), sans-serif`, served from
    Fontshare

CONCLUSION: your stack request is not a migration. It is "use the house stack."
Matching it exactly means shared tokens, shared components and one design
language across smartgrowinfotech.com and this site.

THE STACK TO BUILD ON
  Framework .......... Next.js 15 (App Router) + TypeScript (strict)
  Rendering .......... SSG by default. `export const dynamic = 'force-static'`
                       on all 60 marketing routes. Server Actions for forms.
  Styling ............ Tailwind CSS v4 (CSS-first `@theme`, no JS config)
  Components ......... shadcn/ui (Radix primitives, copied in, fully owned)
  Fonts .............. next/font/google → Inter, JetBrains Mono
                       next/font/local  → Satoshi (self-host from Fontshare)
  Icons .............. lucide-react  [NEW — matches the reference's 2px
                       round-cap line style exactly; it's the same lineage]
  Motion ............. motion (the framer-motion successor), used sparingly
  Carousel ........... embla-carousel-react via shadcn's Carousel
  Forms .............. react-hook-form + zod + @hookform/resolvers
  Form handling ...... Next Server Actions + resend (or your ESP)
  Analytics .......... GA4 via @next/third-parties/google
  Images ............. next/image with AVIF+WebP  [fixes a real reference flaw]
  SEO ................ Next metadata API + app/sitemap.ts + app/robots.ts
  Schema ............. hand-rolled JSON-LD components, typed with schema-dts
  Deploy ............. Vercel

WHY EACH NON-OBVIOUS CHOICE
  shadcn/ui over MUI/Chakra — you already ship its token contract. It's also
    copy-in rather than a dependency, so the accordion, carousel, dialog, sheet,
    select and form primitives become yours to restyle without fighting a
    library's opinions. Radix underneath gives keyboard nav, focus trapping and
    ARIA wiring for free — which is precisely where the reference site failed.
  Tailwind v4 — `@theme` lets brand tokens live as real CSS custom properties
    AND generate utilities from one declaration. No duplicated config.
  motion over GSAP — the reference site used zero animation libraries and was
    better for it. We need three small things (dotted-grid fade-in, availability
    pulse, carousel). `motion` covers it in a few KB; GSAP would be overkill.
  lucide-react — the reference's icon geometry (24×24 viewBox, 2px stroke,
    round caps/joins, and a checkmark using `polyline points='20 6 9 17 4 12'`)
    IS Feather. lucide is the maintained Feather fork.

WHAT WE DELIBERATELY DO NOT ADD
  No Lenis/Locomotive (native `scroll-behavior: smooth` is enough)
  No GSAP/ScrollTrigger · No Three.js/Spline · No Lottie · No preloader
  No custom cursor · No page-transition library
  Rationale: the reference proved a 60-page HVAC site converts fine with 74
  lines of JS. Restraint here is a feature, and it protects Core Web Vitals.

─── 1.5  CONTRAST — COMPUTED, NOT ASSUMED  [NEW] ───

  Ratios calculated from the verified hex values using the WCAG relative-
  luminance formula.

  PASS — use freely
    #212121 Ink on #FFFFFF ................ 16.1 : 1   AAA
    #212121 Ink on #F6F7F9 Cloud .......... 15.2 : 1   AAA
    #50576B Slate on #FFFFFF .............. 7.2 : 1    AAA
    #50576B Slate on #F6F7F9 .............. 6.8 : 1    AA  (AAA large)
    #FFFFFF on #0B1B2B Deep Navy .......... 17.4 : 1   AAA
    #FFFFFF on #000000 .................... 21.0 : 1   AAA
    #FFFFFF on #0067F3 Action Blue ........ 4.96 : 1   AA  ✔ normal text
    #0067F3 on #FFFFFF .................... 4.96 : 1   AA  ✔ normal text

  ★ THIS IS A REAL WIN OVER THE REFERENCE. Their white-on-red primary button
    measured ~4.1:1 and FAILED AA for normal text at 15px/600. Our
    white-on-Action-Blue clears 4.5:1. The brand's own color choice fixes an
    accessibility defect we inherited from the structure.

  CAUTION — large text only (≥24px, or ≥18.66px bold)
    #1690B8 Teal on #FFFFFF ............... 3.67 : 1   AA large only
      → Teal is fine for the logo and for oversized display accents.
        It is NOT a body or UI text color. Do not use it for links.

  FAIL — never use as text on light
    #F18A21 Orange on #FFFFFF ............. 2.50 : 1   ✘ FAILS everything
      → Orange is DECORATIVE ONLY. The eyebrow node, the circuit trace, a
        badge fill with dark text on it. Never a word of copy on white.
        (#F18A21 background with #212121 text = 6.45:1, which passes — so an
        orange chip with Ink text is fine. An orange word on white is not.)

  This constraint is consistent with the brand page's own guidance, which lists
  Orange's role as "Accents, highlights, eyebrow dots" — decoration, not text.
  The math confirms the brand team's instinct. Encode it as a lint rule.

─── 1.6  DARK MODE  [NEW] ───

  The brand page names Pure Black as "Dark mode background", so dark mode is
  clearly intended. The reference site had none — it alternated light and dark
  SECTIONS within one theme instead.

  RECOMMENDATION: ship light-only at launch, but author every token with a
  `.dark` counterpart from day one so enabling it later is a config change, not
  a refactor. Section-level dark bands (`bg-navy`) give us 80% of the visual
  drama with none of the QA cost.

  .dark {
    --background: 0 0% 0%;            /* Pure Black */
    --foreground: 0 0% 98%;
    --card: 209 60% 11%;              /* Deep Navy raises off black */
    --muted: 209 40% 14%;
    --muted-foreground: 220 12% 70%;
    --border: 0 0% 100% / 0.12;
    --primary: 0 0% 98%;
    --primary-foreground: 0 0% 9%;
    /* --ring and --accent stay identical — both clear AA on black */
  }

─── 2.4  WHERE EACH FAMILY IS USED ───

  SATOSHI    every h1–h5 · stat figures · plan prices · pull quotes ·
             the phone number when displayed large (footer, drawer, FAQ card) ·
             card titles · process step numbers
  INTER      all body copy · leads · card descriptions · buttons · nav links ·
             form labels and inputs · footer links · breadcrumbs · FAQ answers
  JETBRAINS  eyebrows · stat labels · badges and chips · table headers ·
    MONO     metadata (dates, read times, model numbers, license numbers) ·
             the availability badge label · section numbering (01, 02, 03)

  THE MONO RULE: JetBrains Mono is for things that are DATA. If it's a number,
  a code, a label or a state, it's mono. If it's a sentence, it's Inter. If
  it's a statement, it's Satoshi. This gives the site an unusually clear
  typographic logic and directly serves the technical-credibility positioning.

─── 2.5  LOADING  [NEW — implementation] ───

  // app/fonts.ts
  import { Inter, JetBrains_Mono } from 'next/font/google'
  import localFont from 'next/font/local'

  export const inter = Inter({
    subsets: ['latin'], variable: '--font-body', display: 'swap',
  })
  export const jetbrains = JetBrains_Mono({
    subsets: ['latin'], weight: ['400','500'],
    variable: '--font-mono', display: 'swap',
  })
  export const satoshi = localFont({
    variable: '--font-display', display: 'swap',
    src: [
      { path: './Satoshi-Medium.woff2', weight: '500', style: 'normal' },
      { path: './Satoshi-Bold.woff2',   weight: '700', style: 'normal' },
      { path: './Satoshi-Black.woff2',  weight: '900', style: 'normal' },
    ],
  })

  ⚠ SATOSHI LICENSING — Fontshare fonts are free for commercial use, but
    SELF-HOSTING requires downloading the webfont package from Fontshare and
    confirming the license terms permit it. Verify before shipping. If
    self-hosting is not permitted, use their CDN <link> and accept the extra
    round trip. Do not skip this check.

  ⚠ SATOSHI FALLBACK METRICS — Satoshi and Inter have different metrics, so a
    swap will shift layout. Either (a) accept a small CLS on Satoshi headings,
    or (b) define a metric-adjusted fallback with `size-adjust`. Recommend (b)
    for the hero H1 specifically, since it's above the fold.

─── 4.1  THE CIRCUIT EYEBROW  ★ replaces the reference's 3px red underline ───

  BRAND SPEC: "Orange node with fading trace and mono label"

  The reference repeated ONE device across 11 selectors: a 12px uppercase label
  above a 3px solid red rule. It was their most-repeated visual signature.
  Ours is the circuit eyebrow, and it does the same structural job with the
  brand's own language.

  ANATOMY
    ●━━━━━━━━──────  NATIONWIDE HVAC · SINCE 2009
    │      │      │  │
    │      │      │  └─ JetBrains Mono 500, 12px, uppercase, +0.12em, Slate
    │      │      └──── trace fades to transparent
    │      └─────────── 1px trace, Orange → transparent, 40px
    └────────────────── 6px filled circle, #F18A21, with a soft glow ring

  .eyebrow {
    display: inline-flex; align-items: center; gap: 10px;
    font-family: var(--font-mono); font-weight: 500; font-size: 12px;
    text-transform: uppercase; letter-spacing: 0.12em;
    color: hsl(var(--muted-foreground));
  }
  .eyebrow::before {
    content: ""; width: 46px; height: 6px; flex-shrink: 0;
    background:
      radial-gradient(circle 3px at 3px 50%, #F18A21 0 3px, transparent 3px),
      linear-gradient(90deg,
        rgba(241,138,33,.85) 0 6px,
        rgba(241,138,33,.35) 40%,
        rgba(241,138,33,0) 100%);
    background-repeat: no-repeat;
  }
  /* on dark surfaces */
  .eyebrow--on-dark { color: rgba(255,255,255,.72); }

  Note the orange sits at 6px as pure DECORATION — never as text. This is
  exactly what the contrast math in §1.5 requires.

─── 4.2  THE DOTTED GRID  ★ replaces the reference's cream photo veil ───

  BRAND SPEC: "Blue-tinted radial fade behind heroes"

  The reference's hero treatment was a low-opacity photo under a four-stop
  cream gradient at 112°. Warm, editorial, photographic. Yours is a technical
  dot grid with a radial falloff. Cooler, more precise, more "infotech".

  .dot-grid {
    position: absolute; inset: 0; pointer-events: none;
    background-image: radial-gradient(
      circle 1px at 1px 1px, rgba(0,103,243,.16) 1px, transparent 0);
    background-size: 24px 24px;
    -webkit-mask-image: radial-gradient(
      ellipse 80% 60% at 50% 0%, #000 0%, transparent 72%);
            mask-image: radial-gradient(
      ellipse 80% 60% at 50% 0%, #000 0%, transparent 72%);
  }

  · 24px grid, 1px dots, Action Blue at 16%
  · Radial mask so it's densest at the top and vanishes before the fold
  · Sits behind hero text, above the background, below content (z-index 0)
  · On dark sections: rgba(255,255,255,.10) instead of blue
  · Hidden under `prefers-reduced-motion`? No — it's static, it stays.

  WHEN PHOTOS ARE USED (service and metro heroes), layer:
    photo at opacity .30, `filter: saturate(.9) contrast(1.03)`
    → a white/Cloud gradient veil at 110°, four stops (.96 / .88 / .62 / .48)
    → the dot grid on top at reduced opacity
    → content at z-index 2
  This is the reference's veil technique, recolored from cream to cool neutral.

─── 4.3  THE AVAILABILITY BADGE  ★ replaces the reference's red pulsing dot ───

  BRAND SPEC: "Pulsing green dot with scarcity messaging"

  The reference had a pulsing RED dot with the label "Calls answered 24/7" in
  the footer CTA block. Yours is green. Same idea, better semantics — green
  reads as "available", red reads as "alert".

  }

    content: ""; width: 7px; height: 7px; border-radius: 50%;
    background: hsl(var(--success));
    box-shadow: 0 0 0 4px hsl(var(--success) / .22);
    animation: availabilityPulse 2.4s ease-in-out infinite;
  }
  @keyframes availabilityPulse {
    0%,100% { box-shadow: 0 0 0 4px hsl(var(--success) / .22); }

################################################################################
##  §14  ACCESSIBILITY & PERFORMANCE
################################################################################

  ★ EVERY ITEM HERE IS A DEFECT WE INHERITED FROM THE REFERENCE AND ARE FIXING.

  A11Y — THE FIX LIST
    1. focus-visible on everything.  The reference had ZERO focus rules except
       two that REMOVED the outline. Ours: 2px Action Blue outline, 2px offset,
       on every interactive element. Radix handles most of it; we style it.
    2. prefers-reduced-motion.  They had none; their 60s marquee and 2.4s pulse
       ran regardless. Ours is in §8 and is mandatory.
    3. Skip link to #main on every page.
    4. Semantic list roles.  They applied `ul{list-style:none}` globally with
       no `role="list"`, which suppresses list semantics in VoiceOver.
    5. Error states not by color alone.  Icon + border change + text, and
       `aria-describedby` wiring the message to the field.
    6. Visible error summary.  They set `.gform_validation_errors{display:none}`,
       hiding the aggregated error region from screen readers entirely.
    7. aria-current on the active nav item.
    8. Real accordion semantics.  Radix gives aria-expanded / aria-controls /
       proper heading buttons. Theirs was a display toggle.
    9. Contrast.  See §1.5 — white-on-Action-Blue clears AA where their
       white-on-red did not. Orange is locked to decorative use by rule.
    10. Alt text on every image; decorative layers marked aria-hidden.
    11. Published accessibility statement at /accessibility.

  PERFORMANCE TARGETS
    LCP < 2.0s · INP < 200ms · CLS < 0.05 · Lighthouse ≥ 95 all four

  PERF — THE FIX LIST
    1. next/image everywhere.  The reference delivered ALL hero photography as
       CSS background-image, which cannot be lazy-loaded, srcset'd or
       priority-hinted. We use <Image> with fill + sizes, AVIF/WebP, and
       `priority` on the hero only.
    2. Logo assets.  Currently 500–720KB print-res PNGs (§4.4). Must be SVG or
       optimized multi-density raster. BLOCKER.
    3. Static generation.  All 60 routes SSG. No runtime data fetching on
       marketing pages.
    4. Font strategy.  next/font self-hosts Inter and JetBrains with automatic
       preload and fallback-metric generation. Satoshi via next/font/local with
       a `size-adjust` fallback to prevent CLS on the hero H1.
    5. Bundle discipline.  Server Components by default. `"use client"` only on:
       mobile drawer, mega-menu, accordion, tabs, carousel, forms, sticky bar.
       Everything else ships zero JS.
    6. No render-blocking third parties.  GA4 via @next/third-parties, which
       loads it correctly deferred.
    7. Skeletons.  aspect-ratio boxes with a Cloud background on every media
       container — the reference did this well and we keep it.
