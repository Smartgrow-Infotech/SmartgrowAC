Visit {{REFERENCE_URL}} and analyze the ENTIRE site's visual design, layout,

--------------------------------------------------------------------------------
METHOD (follow in order; report what worked and what didn't)
--------------------------------------------------------------------------------
1. Fetch the homepage plus 3–5 key inner pages (services, about, a case
   study/work page, contact). From each page's <head> and body collect:
   every <link rel="stylesheet"> URL, inline <style> blocks, font loading
   (Google Fonts / Fontshare / Adobe Fonts links, @font-face, next/font
   markers, size-adjust metas), theme-color meta, favicon links, and every
   <script src>. From script names identify the stack: framework (Next, Nuxt,
   Astro, Webflow, Framer, WordPress), animation libs (GSAP + ScrollTrigger,
   Framer Motion, Motion One, Anime.js), scroll libs (Lenis, Locomotive,
   Smooth Scrollbar), 3D (Three.js, Spline runtime, R3F), Lottie/Rive,
   sliders (Swiper, Splide, Embla), page transitions (Barba, View
   Transitions), and any cursor/preloader scripts.
2. Fetch EVERY stylesheet you found. Extract exact values for: :root CSS
   custom properties, Tailwind utility signatures/config hints, @font-face
   declarations, @keyframes names + what they animate, media-query
   breakpoints, container max-widths, spacing scale, border-radius scale,
   every box-shadow, every gradient, transition durations + easing curves,
   z-index layers, backdrop-filter usage.
3. If the site is client-rendered (Next/Nuxt/Framer) and the plain fetch
   returns only a shell, note exactly which sections exist client-side, use
   whatever IS retrievable (raw HTML head, structural DOM, brand page,
   rendered screenshots if available, indexed search snippets), and mark the
   rest as not verifiable. Do not guess silently.
4. If a stylesheet URL cannot be discovered (hashed bundles referenced only
   in a stripped <head>), say so explicitly, name what you tried, and switch
   to [EST] values for anything CSS-only.
5. Tag EVERY value: [VERIFIED] = read from CSS or the brand page ·
   [OBSERVED] = seen in DOM structure/markup/screenshot · [EST] = estimated
   to match the observed design (say why). Never present an estimate as a
   measurement.

OUTPUT — create a downloadable file: designReference.txt
--------------------------------------------------------------------------------
Fill each section with real values observed from the site. Structure EXACTLY:

0. BUILD & STACK
   Framework · rendering (SSR/SSG/CSR, which sections hydrate client-side) ·
   CSS approach (Tailwind / CSS modules / styled-components / vanilla) ·
   animation, scroll, 3D, slider, transition libraries detected · font host ·
   image pipeline (formats, optimizer, srcset widths, quality) · preloader
   present? · analytics/chat/booking widgets (names only).

   Exact hex for: primary, secondary, accent(s), page background(s), surface/
   card, text primary, text muted, borders/dividers, success/warning/error if
   present, link/hover colors. Dark mode? How each color is used (roles).
   Tints/opacity variants actually used (e.g. accent at 10% for chips).
   Distinguish [VERIFIED] brand-page/CSS values from [OBSERVED]/[EST].

2. TYPOGRAPHY
   Families for heading / body / display / mono · weights loaded · exact
   sizes for H1, H2, H3, H4, body, small, buttons, nav links, eyebrow labels
   (px/rem and any clamp() responsive formulas) · line-heights · letter-
   spacing · text-transform usage · font loading method and fallbacks ·
   where each family is used.

3. SPACING & LAYOUT
   Container max-width · side padding per breakpoint · section vertical
   padding (desktop/mobile) · grid systems (column counts, gaps) · spacing
   scale (base unit, steps) · breakpoints · alignment patterns (centered vs
   left) · full-bleed vs contained sections · homepage section order with
   approximate heights.

4. BUTTONS & CTA STYLES
   Every variant (primary, secondary, ghost/outline, text link, icon-only):
   background, text color, padding, height, border-radius, border, font
   size/weight, icon usage and placement, hover/active/focus states, transition
   timing. Composite CTAs (avatar stacks, "+ you" chips, badges inside
   buttons). Pills/badges (availability, "new", eyebrow tags).

5. CARDS & COMPONENTS
   Cards: padding, radius, border, shadow, background, hover behavior, image
   treatment · chips/tags · avatars (size, ring, overlap) · stat counters ·
   testimonial/quote blocks · chat-style or messenger-style blocks ·
   accordions (FAQ) · tabs · forms & inputs (height, radius, border, focus

   tables · marquees/carousels/sliders · modals/drawers · tooltips ·
   dividers · icon style (line/filled/duotone, size, library) · imagery
   style (photo vs illustration vs 3D, aspect ratios, corner radii,
   overlays, masks).

6. SHADOWS & BORDERS
   Every shadow token with exact values and where it is used (card, hover,
   nav, dropdown, button) · border widths/colors/opacities · full radius
   scale (pill → card → input → media) · divider styles.

7. BACKGROUNDS / GRADIENTS / SHADERS
   Page and section backgrounds · gradients with exact stops/angles ·
   noise/grain overlays · blurred blobs/mesh · oversized watermark or logo

   video backgrounds · image overlays and blend modes.

8. ANIMATIONS & SCROLL EFFECTS
   Preloader (what it shows, duration, exit animation) · page transitions ·

   tickers, typewriter, gradient text) · scroll reveals (properties,
   thresholds, durations, easing, stagger) · parallax · pinning/scrubbing ·
   smooth scroll (library + lerp/duration settings) · marquees (speed,
   direction, pause-on-hover) · hover micro-interactions (scale, lift,
   underline, magnetic) · custom cursor · counters/number animations ·
   3D/Spline scenes (where placed, what the scene is, interactive or
   ambient, mobile fallback, load strategy) · Lottie/Rive · reduced-motion
   handling · overall motion "feel" (durations and easing family).

9. NAVIGATION STYLE
   Position (fixed/sticky/static) · height · background (solid/translucent/

10. HERO LAYOUT
    Text diagram of element order · alignment · height (vh) · eyebrow/badge ·

12. SECTION-BY-SECTION HOMEPAGE MAP
    For every section in order: layout pattern (e.g. 2-col split, 3-col grid,

13. RESPONSIVE BEHAVIOR
    What changes at each breakpoint: nav, grids, type scale, spacing,
    hidden/reordered elements, touch-specific behavior.

14. ACCESSIBILITY & PERFORMANCE NOTES
    Contrast observations, focus-visible styles, prefers-reduced-motion

15. REPLICATION QUICK-START

16. UNVERIFIABLE / NOT RETRIEVABLE
    Everything you could not confirm and why (stripped head, unreachable
    CSS, client-only sections), so nothing in the file is silently guessed.
